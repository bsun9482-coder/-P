## 问题 1：报告出来后再随便说一句话，报告就被一句提示顶掉了

### 长什么样

模拟面试走到最后，报告正常显示。用户再发一句"谢谢，再见"或者"再来一轮"，
报告面板立刻变成空白 —— 分数环没了、维度没了、薄弱点没了、改进建议没了，
只剩个标题和"下载总结报告"按钮；点下载，下载到的是一句
「本轮模拟面试已结束。可以开始新一轮，或切换到辅导答疑模式继续练习。」

### 怎么复现（已实测）

构造一个"已出报告"的会话，再往 `/api/chat` 发一条消息，抓 SSE 事件：

```
done.report      = '本轮模拟面试已结束。可以开始新一轮，或切换到辅导答疑模式继续练习。'
done.report_data = {'score': None, 'dimensions': [], 'weak_points': [], 'improvements': []}
done.finished    = True
```

报告全文在数据库里是好的（`db.report` 正常、`db.score = 80`），
**只是发给前端的那一份被换掉了。**

### 大白话说原因

后端在"这一轮回复结束"时，判断"要不要把报告带给前端"的办法是：

> 看这场对话的最后一条，是不是小P说的话。是的话，就把它当成报告发出去。

报告刚出来时，最后一条确实是报告，所以没问题。
但报告出来之后，用户只要再开口说一句，程序会往对话记录里补一条小P的回复
——内容是「本轮模拟面试已结束……」。这时候"最后一条"就变成这句提示语了，
于是它被当成报告发给了前端。

同一个判断在"刷新页面恢复会话"的地方（`GET /api/session`）又被抄了一遍，
问题一模一样，所以**刷新之后看到的也是这句提示，不是报告**。

### 证据位置

- `app/routers/session.py` 第 225-231 行（聊天流结束时的 `report` 取值）
- `app/routers/session.py` 第 115-117 行（`get_session` 的 `report` 取值）
- 对比：`app/stores/session_store.py` 第 69-80 行**已经写对了**
  ——"从后往前找最后一条内容不是那句提示语的回复"，这才是正确取法。

### 改法（改动很小，不新增功能）

把上面两处"只看最后一条"换成和 `session_store` 一样的
"从后往前找到最后一条不是提示语的回复"。等于把已经验证过的正确逻辑复用一次。

## 问题 2：面试做完一刷新就没了；侧栏历史又点不开，报告永久失联

### 长什么样

1. 模拟面试走完，报告显示正常。
2. 按 F5 刷新页面。
3. 页面回到"开始你的面试训练"的空首页 —— 刚才那场对话、报告，全都不见了。

侧栏"历史记录"里能看到一行「模拟面试 9/23 14:10 80」，但**点了没反应**。

### 怎么复现（已实测）

报告落库之后立刻请求恢复接口：

```
GET /api/session
  active   = False
  finished = False
  history  = 0 条
  report   = None

GET /api/session/history  →  [ {id:1, status:'done', score:80, report:'【总分】80/100…'} ]
```

### 大白话说原因

两件事凑到一起：

1. 报告一落库，这场面试就被程序标成"已归档"。而前端只认"正在进行中的那一场"，
   没有"归档的也能看回来"的入口 —— 所以刷新后前端两手空空。
2. 侧栏历史列表那一块，只画了标题、时间、分数三个字，
   **没有绑定任何点击动作**。后端其实把报告全文、薄弱点都返回了，前端一个字都没用。

所以结果就是：报告变成"一次性消耗品"，刷新即永久失联。

### 证据位置

- `app/stores/session_store.py` 第 87 行（完成即 `status="done"` 归档）
- `app/routers/session.py` 第 106-114 行（无活跃会话时直接返回空）
- `frontend/src/views/ChatView.vue` 第 60-66 行（历史列表，无 `@click`）
- `frontend/src/api/index.js` 第 37 行（`history()` 已拿到全部数据）

### 改法（这里要动一点点功能）

两个方向，看你要哪个：

- **保守**：不动"报告即归档"的设计，只把侧栏历史行做成可点击，
  点开弹出那一场的报告（数据后端已经给全了，纯前端渲染）。
- **更进一步**：让"刚结束的那一场"刷新后仍能直接展示报告（后端恢复接口
  在会话"刚结束"的状态下也把它当作当前会话返回），历史行同样可点。

## 问题 3：报告格式一跑偏，面板就全空（连原文都不显示）

### 长什么样

大模型偶尔不按模板输出（第一行不是 `【总分】NN/100`）。这时候报告面板
只有"面试评估报告"标题 + 下载按钮，分数环不出现、维度/薄弱点/改进全空，
**但报告正文一个字也不给看**。

### 怎么复现（已实测，用 node 复刻了那段判断）

后端在"什么都解析不出来"时返回的不是"空"，而是四个空壳：

```
report_data = {score: null, dimensions: [], weak_points: [], improvements: []}
```

前端判断"要不要把正文原样贴出来"的条件写成了：

```js
if (d && (d.score != null || d.dimensions || d.weak_points || d.improvements))
```

在 JS 里**空数组 `[]` 算"真"**，所以这个条件成立了，前端就认为
"后端给了结构化数据，不用贴原文了"。实测输出：

```
前端判定结果 = {"raw":false,"score":null,"dimensions":0,"weak":0}
  -> 认为"有结构化数据"? true（于是不再显示报告原文）
```

注释里写的"无结构化数据时展示原文"那条兜底路径，**实际上永远走不到**。

### 证据位置

- `frontend/src/components/ReportPanel.vue` 第 97-115 行
- `app/agent/coach.py` 第 142-149 行（`parse_report` 恒定返回四键字典）

### 改法

把条件从"有没有这个字段"改成"有没有内容"（判长度），
或者让后端在四个字段全空时直接返回 `None`。两处任选其一即可，改动都是一两行。

## 问题 4：题库里一道 Python 题都没有，三个阶段在偷偷给 Java 题

### 长什么样

首页写得明明白白：「面试共六个阶段：**Python基础** → 数据结构/算法 → 数据库/SQL
→ 网络与并发 → 项目深挖 → 场景设计」。

实测题库（`data/questions.db`）：

```
总题数: 278
按来源:  javaguide 278        ← 全部来自一个源
含 "Python" 字样的题数: 0
按难度:  '中等' 278           ← 难度也全是同一个值
```

跑真实的六阶段选题，结果：

```
阶段1 「Python基础」   → 降级（碰不到 Python 标签），实得：ReentrantLock 是什么？[Java,并发]
阶段2 「数据结构与算法」→ 命中，实得：说一说 PriorityQueue                [Java,数据结构]
阶段3 「数据库/SQL」    → 命中，实得：SELECT * 会导致索引失效吗？          [MySQL,数据库]
阶段4 「网络与并发」    → 命中，实得：为什么不推荐使用内置线程池？          [Java,并发]
阶段5 「项目深挖」      → 降级，实得：如何检测死锁？                       [Java,并发]
阶段6 「场景设计题」    → 降级，实得：ArrayList 与 LinkedList 区别？        [Java,数据结构]
```

阶段 1 / 5 / 6 **每次都退化成"从整个题库里随便挑一道"**，而且**界面上没有任何提示**，
用户以为自己在答"Python基础"，其实拿到的是 Java 并发题。
阶段 6 更离谱：说好的场景设计题，给的是"ArrayList 和 LinkedList 的区别"。

### 大白话说原因

三件事叠在一起：

1. **唯一能用的数据源只讲 Java。** 代码里的抓取清单（`javaguide.TOPICS`）是
   Java 基础 / Java 集合 / Java 并发 / JVM / Redis / MySQL / 操作系统
   —— 一行 Python 都没有。
2. **唯一带 Python 分类的数据源被挡在门外。** 面试鸭（mianshiya）的分类里
   确实有 `python`，但实测它返回 **567**（站点反爬），
   走代理和直连都一样，跟网络环境无关。
3. **匹配不上时会悄悄放宽，不告诉任何人。** 选题函数的逻辑是
   "先按标签+难度找 → 找不到就只要标签 → 还找不到就全库随便挑"，
   一路放宽下来一声不吭。

顺带：定制面试里"本地题库没命中就按岗位补抓"这条路（`lazy.py`）
把 `python` 映射到的也是那个打不开的面试鸭，所以 Python 岗位同样补不到题。

### 证据位置

- `app/crawler/javaguide.py` 的 `TOPICS`（全是 Java 方向）
- `app/crawler/run.py` 第 16-20 行（三个源：mianshiya 不可用 / javaguide 可用 / nowcoder 是空壳）
- `app/crawler/nowcoder.py`（`fetch()` 直接 `return []`，占位实现）
- `app/agent/coach.py` 第 182-197 行（`_pick_question` 三级放宽，无任何提示）
- `app/services/prompts.py` 第 64-87 行（六阶段的期望标签）
- `app/crawler/lazy.py` 第 20-43 行（`python` → 打不开的面试鸭）

### 改法（分两步，先小后大）

- **小改动（不动功能，只让人看见）**：选题放宽时在回复里说明
  "本阶段暂无匹配题目，已随机出题"，并在题库页标注"当前题库以 Java 为主"。
  这样至少不会让人误以为自己在练 Python。
- **大改动（要选型）**：加一个能用的中文 Python 题库源；或者把
  "自己导入 CSV"提升成一条正经的建库路径（CSV 导入功能其实已经有了）。

## 问题 5：语音和文字版各写各的，同一账号会互相覆盖

### 长什么样

同一个账号，电脑上开着语音通话，手机上用文字版发消息。
两边各自把整份对话读出来、改一遍、再存回去，**后存的那份把前一份的回合盖掉**
—— 轻则少一轮问答，重则刚出的报告被覆盖。

### 证据（代码确凿，未做双端实测）

防止"同一用户同时跑两轮回复"的那把锁（`_chat_locks`），全项目只出现在
**一个文件**里：

```
app/routers/session.py:154   _chat_locks: dict[int, asyncio.Lock] = {}
app/routers/session.py:157   def _get_chat_lock(user_id: int)
app/routers/session.py:183   lock = _get_chat_lock(user_row["id"])
```

语音那条链路（`app/voice_ws.py`）**一次都没有引用**它是自己一套
"读 → 改 → 存"（`_produce` + `_on_produce_done` 里的 `save_session`）。
所以两边互不相认。

### 改法

把"同一用户同时只允许一条回复在推进"这件事挪到一个两边都能拿到的地方
（后端一个公共模块），语音和文字在真正开始生成之前都先去拿这把锁，
拿不到就明确回绝（文字版已经有回绝文案，语音也可以发一条结构化提示）。

这一条是**旧账**：以往复盘就记过（当时的说法是"两套锁没打通"），至今仍在。

## 问题 6：`/api/chat` 的"防重复"有一条缝

### 大白话说原因

现在的做法是两步：

1. 先**看一眼**"上一条回复还在生成吗？"—— 在生成，就回绝；
2. 然后才**伸手去拿**那把锁。

"看"和"拿"之间是分开的两步，中间有极短的空档。两个请求几乎同时到达时，
可能**都通过了第 1 步**，然后排队依次执行。

### 影响

多跑一次大模型调用（多花一次钱），并且后执行的那一轮拿着**过期的对话副本**
去存，会把前一轮的结果盖掉。

### 触发条件

同一账号开两个标签页，几乎同时点发送。前端单页面里的连点已经被
`sending` 挡住了，但两个标签页各自独立，挡不住。

### 说明

这条**没有实测复现**（复现要构造精确的并发时序），是从代码顺序上读出来的缝隙。
如果问题 5 一并处理，这条天然会被一起收掉。

## 问题 7：定制面试弹窗的三个小毛病

同一个文件（`frontend/src/components/CustomInterviewDialog.vue`）：

1. **生成中点右上角 ✕ 关掉，再打开会卡在"生成中"。**
   `generating` 这个标记没被复位，弹窗重新打开后还是进度界面，
   但背后其实没有生成在进行 —— 只能刷新页面。
   （底部的"取消"按钮在生成时是藏起来的，但关闭叉号一直可点。）

2. **生成请求没法取消。**
   发消息用了"可取消"的写法，定制生成这条路**没有传取消信号**，
   用户点了"返回首页"或者干脆退出登录，后台仍会继续跑完并继续计费。

3. **进度条是假的。**
   `progressPct` 写的是"有没有进度文案 → 有就是 100%，没有就是 0%"。
   所以生成一开始进度条就是满的，永远看不到实际进度，纯装饰。

改法：关闭时复位标记并中断请求（后端流也要能感知断开）；把进度文案映射成
真实档位（比如 4 个步骤各 25%），或者干脆去掉这个进度条。
